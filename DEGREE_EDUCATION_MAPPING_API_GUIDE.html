Degree & Education Mapping

Simple API explanation for frontend and backend developers

There is no separate Degree–Education Mapping controller. A degree is connected to an education level by saving the education level's ID in the Degree record as levelOfEduId.

1. APIs used by the screen

PurposeAPI
Load the Education Level dropdownGET /api/v1/level-of-educations
Load all degreesGET /api/v1/degrees
Load degrees for one Education LevelGET /api/v1/degrees?levelOfEduId={levelId}
Create a degree mappingPOST /api/v1/degrees
View one degreeGET /api/v1/degrees/{id}
Update one degreePUT /api/v1/degrees/{id}
Delete one degreeDELETE /api/v1/degrees/{id}

2. How the mapping works

  1. The frontend loads the available Education Levels.
  2. The user selects an Education Level, such as “Bachelor”.
  3. The frontend sends that level's ID as levelOfEduId when saving the degree.
  4. The backend stores the Degree and its relationship to the selected Education Level in the same Degree record.

3. Example create request

POST /api/v1/degrees
Content-Type: application/json

{
  "levelOfEduId": 1,
  "degreeName": "Bachelor of Science",
  "shortName": "BSc",
  "sortOrder": 1,
  "status": 1
}

4. Important scope limitation

The current Swagger contracts for Education Level and Degree do not contain bgId or buId. Therefore, these records are currently global and cannot be filtered by the logged-in user's Business Unit.
